# M3: generator diagnostics and two-member handoff

This milestone now has a repository-native, reproducible implementation. It reads
**frozen strict M2/M4 inputs**, not the legacy reproduction tables. The generator,
classifier and upstream experiment files are unchanged. Results live in
[`results/m3/REPORT.md`](../results/m3/REPORT.md).

中文阅读与两人分工：[M3_中文说明.md](M3_中文说明.md)。

## What this adds

1. Independent chronological replay and exact checks against every anomaly audit.
2. Paired endpoint-activity errors, ECDFs, per-seed effects and split diagnostics.
3. Degree, common-neighbor, Jaccard, full/recent pair-history residuals.
4. Timing: recency, 1h/24h concentration, and inter-event-interval burstiness.
5. Diagnostic-window sensitivity at 100, 1,000 and 10,000 events.
6. Common benign-history counterfactual rescoring to distinguish the contribution
   of divergent injected histories from differences in the selected endpoints.
7. Machine-readable missingness, distribution distances and seed variability.
8. Input/source/environment/output manifests and an independent result verifier.
9. Behavioral tests and a documented handoff to M4/M5.

## Reproduce

Use Python 3.11 and the repository pins. Run from the repository root:

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -r configs/m3_environment.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m src.m3 --output results/m3_reproduced
.venv/bin/python -m src.m3_verify results/m3_reproduced
```

The checked-in output is `results/m3`. The CLI refuses to overwrite an existing
output directory or write inside frozen inputs. A failed run may leave partial
outputs; preserve or remove them intentionally before rerunning to that path.
`--windows 1000` gives a smaller diagnostic run; the checked-in run uses all three
windows. Data and graph operations run locally on CPU. `requirements.txt` keeps
its existing versions; the supplemental environment records the numerical/plot
packages used for this M3 run (including SciPy, previously only transitive).

## Input and timing contract

- Inputs: `results/final_m2_m4/{1,5,10}p_seed_{42,43,44}` streams/audits and
  the frozen protocol/manifest. Each read stream and audit must match its frozen
  SHA-256 before analysis. The original benign rows must match the dataset.
- Both strategies must share the same timestamp/reference sequence; stream
  anomalies must match audit pairs, and reference edges must be benign events
  at that timestamp. No self-loop, unseen anomaly node, historical pair or
  same-time benign collision is accepted.
- Queries see **only t' < t**. Score the whole timestamp batch before insertion.
  Observed history includes prior normal and injected events. Normal references
  are scored in each condition's own history, so two reference curves are needed.
- The primary window is 1,000 events and primary split is test. Train/validation
  remain descriptive context. Generator parameters remain frozen at W=1,000,
  10 bins. Neither sensitivity nor test diagnostics reselects a generator.
- The common benign-history control rescores **the same saved edges** against
  benign events alone. It is not a counterfactual regeneration experiment.
  Its normal reference values must agree exactly across conditions.
- Reference edges are sampled at injection timestamps; they are not an unbiased
  sample of every normal edge. The same reference may be sampled repeatedly.

## Metric dictionary

| Metric | Definition / units | Scope |
|---|---|---|
| activity_low/high | Sorted endpoint incident-event counts | Recent W events |
| activity_error | Mean absolute log1p count difference after undirected alignment | Matched reference/anomaly pair |
| degree_mean | Mean number of distinct neighbors of two endpoints | Recent W events |
| common_neighbors | Size of endpoint neighbor intersection | Recent W events |
| jaccard | Intersection/union; empty union defined as zero | Recent W events |
| pair_count | Previous interactions of unordered pair | All prior history |
| recent_pair_count | Previous interactions of unordered pair | Recent W events |
| recency_minutes | Mean time since each endpoint's last event | NaN if either unseen |
| concentration_1h_24h | Mean endpoint count in [t−1h,t) / [t−24h,t) | Zero if denominator zero |
| burstiness | Mean endpoint B=(SD−mean)/(SD+mean) of intervals | At most last 20 intervals per endpoint |
| unseen_endpoint | Either endpoint unseen in prior history | Binary; retained as diagnostic |

Burstiness uses population SD. At least five intervals (six events) are needed
per endpoint. Same-timestamp historical events contribute zero intervals. An
all-zero interval sequence has undefined B and remains NaN. Both endpoints must
have defined B to calculate the edge mean. Intervals include previous observed
anomalies in observed history; benign-only excludes them. This is an additional
M3 diagnostic, not a TGF classifier feature. Concentration and interval B are
complementary descriptions; neither is a universal measure of temporal behavior.

## Statistics and safeguards

Each metric has mean, median, p90, zero fraction, total/valid counts and missing
fraction. KS is reported as a distance only; no independent-edge p-values.
Wasserstein uses log1p for nonnegative counts/recency and raw scale for ratios,
burstiness and the unseen flag. Distances for burstiness compare defined samples;
always inspect missingness before interpreting them.

Paired effects use a shared rate and injection seed. Mean/SD/min/max across the
three seeds describe injection randomness, not classifier randomness, permutation
repeats or population confidence intervals. Nine-cell aggregates in the residual
report average the 3 rates × 3 seeds equally; rate-specific tables remain available.
A4's error bars combine rate and seed variation and are labeled accordingly.

Per-reference rows are deterministic gzip (fixed header timestamp), with explicit
split, strategy, history policy, window and pairing ID. The verifier checks hashes,
bounds, novelty, reference identity and recomputes all statistical tables from
saved rows. Changing code after saving a run invalidates source hashes and requires
a new run. PNG rendering may vary across platforms; exact environment is recorded.

## Current repository integration caveat

The M5 work merged on main uses `results/full_pipeline`, a 70/30 row split,
current-event-inclusive upstream features and a different threshold protocol.
This M3 uses `results/final_m2_m4`, strict historical features and 60/20/20 timestamp
splits. M3 findings must **not** be combined numerically with legacy M5 ablation
scores as one controlled experiment. Rerun/adapt M5 to the strict package first.

Pair-history is a particularly useful M5 ablation target: anomalies are novel by
construction whereas normal references often repeat. This does not prove model
reliance. Common-neighbor/Jaccard and timing diagnostics are not in the current
TGF feature columns; the existing `global_graph` family is not a neighborhood
feature group. No classifier retraining is part of M3.
