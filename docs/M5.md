# M5 local handoff

This analysis uses the existing Generator-1, seed-42 feature tables from project
commit `178ef4f0d`. It supplies a runnable starting point for both M5 members;
feature groups and final experiment scope remain open to team alignment.

## Run

Use Python 3.11 and the project dependency versions. The exact analysis environment
is captured in `configs/m5_environment.txt`; it contains the subset needed here.
The analysis reads saved feature tables and does not need to extract features again.

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r configs/m5_environment.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m src.m5 --feature-sets H1000 combined_H
```

The default is 5% injection, with output in `results/m5/5p_seed_42`. Recreate all
three existing injection rates with:

```bash
for rate in 1 5 10; do
  .venv/bin/python -m src.m5 \
    --run-dir "results/full_pipeline/${rate}p_seed_42" \
    --output "results/m5/${rate}p_seed_42" \
    --feature-sets H1000 combined_H
done
```

For a writable Matplotlib cache on restricted systems, prefix the command with
`MPLCONFIGDIR=/private/tmp/m5-mpl`. To regenerate plots and reports without training:

```bash
.venv/bin/python -m src.m5_report results/m5/5p_seed_42
```

## Feature dictionary and grouping

Definitions were checked against the pinned upstream
[`main.py`](https://github.com/StephanyRajeh/TGF/blob/af9d575e07c7bc3fd0b4a0b8d0249e7cdd2eb88b/3-FeatureGeneration/main.py)
and [`DSC_lib.py`](https://github.com/StephanyRajeh/TGF/blob/af9d575e07c7bc3fd0b4a0b8d0249e7cdd2eb88b/3-FeatureGeneration/DSC_lib.py).
The exact membership is in `configs/m5_groups.json`. Every predictor belongs to
exactly one family; the label `H5_is_fraud` is excluded. Unknown columns require
an explicit mapping. No groups were selected by test performance.

| Family | Per H window | Meaning |
|---|---:|---|
| endpoint_activity | 12 | Degrees and weighted degrees of both endpoints; counts of nodes with the same or greater degree/weighted degree |
| pair_history | 3 | Pair weight; counts of links with equal or greater weight |
| global_graph | 19 | Window size, node/link counts, total weight, and degree/weighted-degree/link-weight distribution summaries |

H1000 has 34 predictors. Combined H has 204 predictors from H5, H50, H100,
H1000, H10000 and H15000. The same family is removed or permuted across all
windows together. The groups are semantic families: endpoint/pair rank features
also use graph-wide distributions, so families are not statistically independent.

- Degree counts distinct neighbors; weighted degree counts incident events.
- Pair weight counts interactions of the unordered pair within the window.
- `same` counts counters with that value; `greater` is the first position in the
  descending counter list, hence the number with a strictly larger value.
- `nb_one` / `nb_two` count values equal to one / two; min, max and median summarize
  the corresponding counter distribution (median follows upstream's index rule).
- `u` and `v` endpoint feature slots are reordered by degree in `fill_result`;
  they are not fixed sender/receiver roles.
- Upstream adds the current event before extracting predictors. Thus pair history
  includes the current event. These are existing features, not a newly implemented
  strict pre-arrival feature set.
- No common-neighbor/Jaccard predictor is present. The global_graph family should
  not be renamed "neighborhood" to match the milestone wording.
- Constant columns are recorded and retained to reproduce the M4 feature schema.

## Experiment contract

Both R and M tables use M4's existing rounded 70/30 row split. Training normals
are sampled down to the number of anomalies with state 12, then shuffled with
state 42. The classifier is the existing default RandomForestClassifier with
state 42. M4 and M5 share `src/modeling.py`; the earlier generic `ablation.py`
remains available but is not used because it does not perform M4's balancing.

For each of R→R, R→M and M→M, train the full model and three leave-one-family-out
models. All variants use the same training sample and test rows. Compare AP
(named PR-AUC by the repository), ROC-AUC and recall at the existing 1% FPR rule.
Actual FPR is retained because ties can exceed the requested rate. The threshold
is derived from test negatives in M4; this analysis preserves that descriptive
metric rather than claiming a validation-calibrated deployment threshold.

Grouped permutation uses the full model and five test-row shuffles (seed 31415).
All columns of one family use the same permutation, preserving relationships
within that family. Its standard deviation describes shuffle variation only.
This is a post-hoc analysis, not feature selection for a final model.

Individual impurity importances (MDI) are saved as a secondary inspection aid.
They can favor continuous/high-cardinality predictors and correlated features;
use grouped permutation plus retrained ablation for the main discussion.

## Outputs

| File | Contents |
|---|---|
| inventory.csv | Every column's group, row/positive counts, missing/nonfinite values, unique values and constant flag |
| ablations.csv | All full/ablated metrics, row counts and full-minus-ablated deltas |
| baseline_check.csv | Full-model metric parity with saved M4, tolerance 1e-10 |
| permutation.csv / permutation_summary.csv | Raw shuffles and family-level AP drop mean/SD |
| mdi.csv | Full-model per-column impurity importance |
| manifest.json | Input/source hashes, environment versions, groups, seeds and split |
| REPORT.md / effects.png | Readable result tables and plots |
