# 项目研究概览：让异常检测面对“没那么容易的异常”

## 1. 这个项目在研究什么

项目使用 UCI Messages 时间网络：每条记录可以理解为“用户 A 在某个时间与用户 B 发生了一次交互”。任务是判断一条边是正常交互，还是人工注入的异常交互。

项目起点是 TGF 论文/代码所采用的简单图统计特征和 Random Forest 基线。我们的工作不只是复现一个高分，而是追问：

> 如果人工异常的生成方式太简单，模型的高分究竟来自真正理解异常，还是来自识别生成器留下的明显痕迹？

例如，随机生成异常边时，可能经常选中近期几乎不活跃的节点。模型只需要发现“两端都很冷门”，就能轻易判断异常；但真实异常未必具有这种特征。这就是 synthetic anomaly evaluation bias。

## 2. 原始方法可以怎样通俗理解

### 2.1 把最近的交互变成一张图

对每条待判断的边 `(u, v)`，算法查看它之前的一段历史，例如最近 1,000 条交互，构建一张临时图。当前事件和同一时间的事件都不能提前进入历史，否则相当于偷看答案。

### 2.2 从历史图提取简单统计特征

项目使用六个历史窗口：5、50、100、1,000、10,000、15,000 条事件。每个窗口提取三类信息：

1. **Endpoint activity**：两个端点最近连接了多少不同节点、发生了多少次交互，以及它们在全图活动分布中的相对位置。
2. **Pair history**：这两个节点过去是否交互过、交互过多少次，以及该次数在全图边权中的相对位置。
3. **Global graph**：窗口内节点数、边数、总交互量，以及度、活动量和边权分布的最小值、最大值、中位数等。

H1000 只使用 1,000-event 窗口，共 34 个特征；combined-H 合并六个窗口，共 204 个特征。

这些特征像是给每条边制作一张“历史体检表”，不使用深度神经网络。

### 2.3 用 Random Forest 分类

Random Forest 可以理解为 100 棵决策树投票。每棵树会学习类似下面的规则：

- 两个节点是不是非常不活跃？
- 这对节点以前是否交互过？
- 当前窗口是否比平时稀疏？

训练时正常样本远多于异常样本，因此项目固定下采样正常训练样本，使两类数量平衡。分类阈值只用 validation 正常样本校准，test 只用于最终评估。

## 3. 我们新增的核心算法：活动匹配异常生成

### 3.1 随机异常生成器

随机生成器从历史已出现节点中选择两个节点，组成一个过去没有出现过的新边。它简单、常见，但容易生成与正常边活动水平差异很大的“送分异常”。

### 3.2 Activity-matched 生成器

活动匹配生成器先在某个注入时间选择一条正常 reference edge，再观察 reference 两端在过去 1,000 个事件中的活动量。

随后把历史节点按活动量分为 10 个等级箱，并从对应等级中为异常边选择两个端点。候选边必须满足：

- 两个节点此前已经出现；
- 不能是 self-loop；
- 这对节点过去没有连接过；
- 不能与同一时间的正常边或其他异常边重复；
- 找不到合格候选时必须失败，不能偷偷退化为随机生成。

通俗地说，随机生成器可能拿“两位几乎不说话的人”制造异常；活动匹配生成器则尽量找“与正常边两端同样活跃的人”，让异常不再那么容易被活动量识别。

参数选择只看 train/validation prefix。最终选择为 1,000-event activity window 和 10 个 bins，没有用 test 选择生成器参数。

## 4. 三种训练—测试设置回答什么问题

1. **Random → Random（R→R）**：在简单随机异常上训练，也在同类异常上测试。它反映传统评估可能得到的成绩。
2. **Random → Matched（R→M）**：在随机异常上训练，却测试更难的活动匹配异常。它衡量模型是否依赖随机生成器的捷径。
3. **Matched → Matched（M→M）**：训练和测试都使用匹配异常。它衡量更贴近目标分布地重新训练后能恢复多少性能。

核心指标包括 AP/PR-AUC、ROC-AUC，以及用 validation 校准的 1% FPR 阈值下 recall。AP 在异常比例较低时尤其重要。

## 5. 当前已经观察到什么

最终 M2/M4 覆盖 1%、5%、10% 注入率，seeds 42–44，两个特征集合和三种设置，共 54 条结果。

活动匹配确实减小了端点活动差异：随机异常的平均 activity error 大约为 1.90–2.10，而匹配异常约为 0.62–0.67。

模型从 R→R 切换到 R→M 后，AP 在所有配置都明显下降。例如 5% 注入、combined-H：

- R→R AP：`0.7025 ± 0.0275`
- R→M AP：`0.2808 ± 0.0055`
- M→M AP：`0.5572 ± 0.0138`

这表明随机异常上训练的模型不能直接泛化到活动匹配异常；使用 matched 数据重新训练可以恢复相当一部分性能，但通常没有完全恢复到 R→R。

combined-H 通常优于只用 H1000，说明短期与长期历史信号存在互补。不过这些结果还不能单独证明性能下降完全由 endpoint activity 引起，因为 matched 与 random 之间还可能存在 neighborhood、pair repetition 和 temporal burstiness 等残余差异。

## 6. M5 进一步回答了什么

M5 分别删除 endpoint activity、pair history、global graph 特征组并重新训练，再与 grouped permutation importance 对照。正式实验覆盖三种注入率、三个 seed、两个特征集合和三种训练—测试设置，共得到 216 条消融结果和 810 次联合置换测量。

它主要观察到：

- R→R 的高分高度依赖 endpoint activity。以 5% / combined-H 为例，删除该组后 AP 平均下降 0.4980；
- R→M 中 endpoint activity 的作用明显减弱，而 pair history 更重要。同一配置删除两组的 AP drop 分别为 0.0804 和 0.1501；
- M→M 的恢复同时使用 endpoint activity 和 pair history，同一配置的 AP drop 分别为 0.3615 和 0.3683；
- global graph 的消融/置换影响通常接近零且偶尔为负，不是稳定的主要信号；
- 三个 seed 上的主要方向一致，但 recall@1% FPR 在低正例数下波动较大。

消融不是简单把训练好的模型某列清零，而是删除整组特征后重新训练，因此可以观察剩余特征能否替代被删除的信息。Permutation importance 则固定完整模型，只打乱某一组，用于观察现有模型对该组的依赖。两者回答的问题不同，结果不必完全一致。

## 7. 当前研究进度

- **M1**：TGF baseline reproduction 已完成。
- **M2**：random/activity-matched controlled injection 与严格历史规则已冻结。
- **M4**：三注入率、三 seed、两特征集、三设置的最终比较已完成。
- **M3**：完整分布诊断、neighborhood、pair-history residual 和 burstiness 解释尚未完成。
- **M5**：最终多 seed 消融、联合置换、MDI、漂移审计、中文报告和独立校验已完成。

M3 仍是当前主要前置依赖。M5 证明的是模型对特征组的依赖关系，不能单独说明生成器为什么改变了 neighborhood overlap、重复交互或 temporal burstiness；这些机制解释仍需 M3 diagnostics。

## 8. 研究贡献可以怎样概括

当前项目的主要贡献不是提出一个更复杂的分类器，而是建立一个更公平、可审计的异常检测评估流程：

1. 揭示随机异常注入可能让任务虚假地变简单；
2. 设计活动匹配生成器，主动减少端点活动这一明显捷径；
3. 对齐 random/matched 的时间戳、候选规则、历史和数据切分；
4. 使用严格 past-only 特征和 validation-only 阈值避免泄漏；
5. 通过跨生成器测试、matched retraining、诊断和特征消融解释性能变化；
6. 保存每个输入、seed、哈希、预测和指标，使实验可以复核。

研究结论目前只适用于 UCI Messages、固定 TGF-style 特征和 Random Forest。三个 seed 能提供初步稳定性证据，但不能代表大规模统计结论，也不能替代真实异常数据上的外部验证。
